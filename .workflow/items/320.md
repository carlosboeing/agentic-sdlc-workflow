## Story: Create SKILL.md for /briefing skill

**Blocked by:** #319 (E01-S01: config schema must exist so the skill can reference it)

**Branch:** `e01-s02/briefing-skill-md`

### What

Create the skill prompt file at `.claude/skills/briefing/SKILL.md` that implements the full briefing skill. This is the core deliverable -- a structured prompt that instructs the AI on mode detection, data source discovery, depth handling, output structure, and behavioral guardrails.

### Files to create

- `.claude/skills/briefing/SKILL.md` -- the skill prompt file (new directory + new file)

### Skill file structure

The SKILL.md must contain these sections (derived from design doc section 4.7):

1. **Purpose statement** -- what the skill does, when to use it, invocation syntax (`/briefing [quick|deep]`)
2. **Mode detection** -- step-by-step instructions for determining briefing vs debrief mode:
   - Check for open PRs from `backlog/*` branches: `gh pr list --head 'backlog/' --state open`
   - Check for state files with incomplete phases: `.agentic-workflow/runs/*/orchestrator.json`
   - If either signal present: debrief mode; otherwise: briefing mode
3. **Depth configuration** -- how to read config and apply depth presets:
   - Read `briefing.defaultDepth` from `.claude/agentic-sdlc-config.json`
   - Override with argument if provided (`/briefing quick`, `/briefing deep`)
   - Source priority table with depth-level columns (from design doc section 4.3.1)
   - Config source toggles override depth presets
4. **Data source checklist** -- ordered by priority, with what to extract from each:
   - Tier 1 (frontmatter-driven): grep commands for frontmatter fields
   - Tier 2 (fixed-path): exact file paths and commands for each source
   - Tier 3 (CLAUDE.md-referenced): scan CLAUDE.md for doc references
5. **Cross-source synthesis** -- instructions for connecting findings across sources
6. **Output template: Briefing mode** -- section structure (TL;DR, Project Pulse, What Happened Last, Roadmap & Priorities, Outstanding Issues, Decisions & Attention Needed)
7. **Output template: Debrief mode** -- SBAR-inspired structure (TL;DR, Summary, Key Findings, What Went Well, What Needs Attention, Merge Readiness, What's Next)
8. **Tone and style** -- concise, direct, lead with most important, no filler
9. **Anti-patterns** -- do NOT list (no memory-only, no file modification, no metric computation, no source skipping)
10. **Conversational continuation** -- remain available for follow-up questions

### Acceptance criteria

- [ ] `.claude/skills/briefing/SKILL.md` exists and is a valid markdown file
- [ ] Skill is discoverable as `/briefing` by Claude Code (correct path structure)
- [ ] Mode detection instructions include both PR check and state file check
- [ ] All 13 data sources from the priority table (design doc section 4.3.1) are listed with extraction instructions
- [ ] Three depth levels (`quick`, `standard`, `deep`) are defined with source inclusion rules
- [ ] Config reference points to `.claude/agentic-sdlc-config.json` briefing section
- [ ] Briefing mode output template matches design doc section 4.5 (all 6 sections)
- [ ] Debrief mode output template matches design doc section 4.5 (all 7 sections)
- [ ] Anti-patterns section explicitly prohibits file modification, comment posting, and metric computation
- [ ] Tier 1 discovery uses frontmatter grep commands (not hardcoded paths per doc type)
- [ ] Tier 3 instructs the AI to scan CLAUDE.md for referenced project docs
- [ ] Cross-source synthesis section covers: recurring patterns, trend detection, dependency chains, artifact readiness, consistency checks
- [ ] Word count guidance matches design doc: quick (200-400), standard (600-1000), deep (1000-2000)

### Test plan

- Verify file exists at `.claude/skills/briefing/SKILL.md`
- Confirm all 10 sections listed above are present in the file
- Cross-reference the data source checklist against design doc section 4.3.1 (all 13 sources)
- Cross-reference output templates against design doc section 4.5
- Verify no bash commands in the skill file have side effects (no `gh issue comment`, no `git commit`, no file writes)
- Confirm the config path referenced in the skill file matches the actual config file location
