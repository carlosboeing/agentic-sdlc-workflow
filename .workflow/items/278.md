## Description

Restructure `.claude/agents/orchestrator.md` to implement the 7-phase model from the design doc (section 6.2). The current Phases 5 (Dispatch Builders), 6 (Review Story), and 7 (Merge Story Branches) collapse into a single Phase 3 (Implementation). Later phases are renumbered accordingly. Phase 3 adds: parallel review dispatch after parallel builds, review tier logic, and parallel fix cycle handling.

**Key constraint:** No story should instruct builders to dispatch reviewer agents. The orchestrator dispatches all agents directly. This is a hard platform constraint (subagent nesting cap at 1 level).

## Files to modify

- `.claude/agents/orchestrator.md` — rewrite Workflow Phases section

### Strengths

- **Clean phase collapse.** Old Phases 3-4 (Read Plan, Create Branches) are naturally folded into Phase 2 as post-plan-merge steps, reducing cognitive overhead without losing any content.
- **Phase 3 wave flow is well-structured.** The four-step pattern (build -> review -> fix -> merge) with clear sub-numbering makes the orchestrator's decision tree unambiguous.
- **Review tier decision logic is explicit and self-contained.** The pseudocode with difficulty ordering note and scope limitation is clear enough for deterministic execution.
- **Fix cycle parallelism is correctly specified.** Step 3 dispatches fix builders in parallel then re-reviewers in parallel, matching the design doc's Approach H specification exactly.
- **Per-epic telemetry and merge moved into the wave loop.** Step 4 point 5 handles epic completion inline, which is more natural than the old separate Phase 8 step.
- **Board reconciliation added after PR opening.** Phase 4 step 4 adds the 5-second wait + reconcile pattern from CLAUDE.md that was missing from the old orchestrator.md.
- **Already-closed issue convention fixed in PR body.** The `Closes` vs `Related (already closed)` distinction is now correct, preventing board status drift.
